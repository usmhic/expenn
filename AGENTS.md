# Repository guide for coding agents

## Product

Expenn is an open-source, self-hosted expense and travel-management platform for
teams, maintained by usmhic.

## Map

- `api/Expenn.Api`: .NET modular API; owns auth, business logic, EF Core schema, and messaging.
- `api/Expenn.Api/Modules`: domain-owned persistence mappings and schema catalog.
- `web`: Next.js App Router client.
- `mobile`: Expo client with native release automation.
- `docker-compose.yml`: supported local integration stack.

Read `ARCHITECTURE.md` before changing service boundaries or startup order.

## Commands

Use versions pinned in `mise.toml` and `api/global.json`.

- Full stack: `docker compose up --build`
- API checks: `dotnet restore api/Expenn.sln && dotnet build api/Expenn.sln --no-restore`
- Web checks: `cd web && pnpm install --frozen-lockfile && pnpm run types:check && pnpm run lint && pnpm run build`
- Mobile type check: `cd mobile && pnpm install --frozen-lockfile && pnpm run types:check`
- Compose validation: `docker compose --no-interpolate config --quiet`

## Guardrails

- The .NET API is the source of truth; web and mobile are clients.
- Keep EF Core model and migration changes together.
- Put each new table in its owning domain schema and update `api/MODULES.md` when
  adding or changing a module boundary.
- Preserve the Result/domain-event patterns described in `api/README.md`.
- Native projects are generated by Expo prebuild; do not commit generated trees.
- Never print or persist signing materials from CI.
- Update environment templates, docs, and tests with configuration or behavior.
